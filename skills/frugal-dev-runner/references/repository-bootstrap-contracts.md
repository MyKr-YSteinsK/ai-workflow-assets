# Repository Bootstrap Contracts｜按需接入与恢复

项目接入、恢复入口或运行档案需要补缺时使用。它是自包含的后备方法；已有项目的实际目录、有效合同和历史编号优先。

## 落地

先确认目标工作区、已有 AGENTS／用户改动、适用合同和真实环境。新项目可从用户直接任务或正式 Plan 接入；在本地合同尚未存在时，用可访问的源材料和自包含的目标、权限、硬边界、验收及交付完成首个任务。只在授权内创建或合并，不推导 Git 初始化、远端创建、部署等权限。

新项目把项目专属的有效源落到项目 `docs/`；短根 `AGENTS.md` 写目标、重要边界、恢复必读项和必要验收出处。既有项目优先指向实际等价文件，保护已批准目标和用户修改。实际落地后从根入口逐条核对必读路径、目标、当前状态、运行方法和数据入口，再报告本地接入。ChatGPT 附件仅在 Codex 确实可读取时才是任务输入；用户按需手动同步项目快照，标明实际版本。

## 恢复时读哪一块

- **目标与决定**：项目目标、需求和验收、保护边界、长期决定及其原因。重要项目可以分开存；简短项目可以合并。没有实现的批准目标仍是目标。
- **当前事实**：基线、当前能力与证据、限制、路线／任务 ID 和修订、依赖与下一入口。当前分支、运行 ID 和实验／部署证据各自核实；候选结果与正式接受分开。重大事实变化在授权内写回。
- **运行档案**：稳定环境（OS、资源、适用 GPU／显存、驱动、运行时和依赖锁）、数据逻辑身份／版本／结构／映射／许可、核验依据、canonical 环境、已验证安装／启动／测试或实验命令、输出。长任务补日志、后台或作业查询、Checkpoint 与 Resume。密钥、私有患者数据、受限路径等用安全引用，未核实的值明确标记。
- **复用与故障**：优先读取已有档案，检查版本漂移和本次需要的动态事实，例如 GPU 占用、进程、磁盘。跨任务可复用的故障记录触发条件、经验证的原因、可靠修复及范围；普通命令错误无需留档。真正无法确定必要授权或验收时只暂停受影响操作。

这些是职责，不要求固定文件或报告数量。按项目现有入口加载；在恢复时先读目标和当前事实，仅在要运行或调查时进入相关环境与证据段落。
