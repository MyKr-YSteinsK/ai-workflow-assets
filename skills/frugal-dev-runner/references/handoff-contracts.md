# Task Handoff｜任务交接与续接

## 接收任务

以实际输入和有效项目要求为准，按项目、任务 ID、修订、来源和基线识别输入。修订未标明时说明实际来源。核对目标、必要约束、授权、验收和交付；交接本身不扩展 Git、发布或数据操作权限。

Hub 核对依赖、重复工作、写入范围与共享资源；可复用工作执行一次，分别对应各任务的验收和证据。隔离输出、可写环境和算力后再并行，不兼容的评价协议分开。如有重名或约束冲突，指出实际差异，只暂停依赖冲突的工作。

## 换对话或收口

在已有状态中记录仍需执行的任务 ID／修订、依赖、证据、下一步及重取 Plan 的线索，例如用户可重交的文件名或获授权的来源。用户在项目外保存正文；公开仓库省略私有路径。状态能说明进度，不能单独证明授权。接手时读取有效输入；如果拿不到、且项目合同不足以覆盖任务权限和验收，请用户重交，只暂停受影响动作。

对话回执写明结果、关键验证及交付缺口；正式交接注明实际 ID／修订，研究任务附可比条件、证据和停止依据。阶段评审确有需要且接收方无法充分读取仓库时，补来源版本、结论、限制及待决事项即可。区分执行、证据接受和阶段推进；项目有必要的持久化报告时写到既有位置，最终提交与远端观察留在回执中。
