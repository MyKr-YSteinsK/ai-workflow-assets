# Codex Plan｜任务交接与结果回传

本规范用于新项目及经授权升级的项目。遵守已有项目的目标、权限、必要验收与交付要求，保留编号和历史记录。

## 1. 什么时候需要 Plan

普通功能、Bug 修复或临时任务可用短 Prompt 直接交给 Codex；已经在 Codex 中进行的任务可直接继续。复杂度、风险、协作或交接需要足够高时，再写正式 Plan。

Issue 链接即可识别任务；项目已有有效编号就沿用。仅在精确冻结、多版本并行或高风险审计确有需要时固定正文版本或记录修订。普通交接无需哈希、登记表、修订审批或额外验收。

### 正式交接：Issue → 短 Prompt

GPT Main 完成规划后，确认目标仓库、可见性及创建权限，优先直接创建 Issue，把完整 Markdown Plan 写入正文。创建成功后交付实际链接和一段可复制的 Codex Prompt：

> 在「项目工作区」执行「任务」。先读取「Issue URL」的完整正文，按当前项目约定在「必要边界」内完成并验证。

Codex 核对工作区与 Issue 所属项目后，读取完整正文，再按实际授权自主实施；标题、摘要或评论不替代正文，也不自动扩大权限。公开仓库的 Issue 对外可见；私有计划或受限信息只交付到获授权的私有位置或本地。无法创建或读取 Issue 时，改用完整 Markdown 正文、可读文件或其他授权渠道。必要输入未补齐时只暂停受影响部分；便利步骤或非关键元数据缺失不阻塞有足够输入的工作。

有已授权的仓库外本地目录时，Codex 读取 Issue 后按约定命名保存一份完整 Markdown 正文；用户本次指定的目录优先。无约定直接执行，副本保存失败也不阻塞正文已取得的授权工作。正式 Plan 默认不提交到目标项目 Git 历史，除非项目有明确约定。

## 2. 交接需要回答什么

无需固定章节。一份 Plan 应足以回答：

- **任务是谁、做成什么**：项目、任务及预期结果、目标工作区和必要背景；适用时注明基线与项目编号。把待查的路径、依赖、运行状态与已核实事实分开。
- **哪些边界必须维持**：明确数据、范围、风险、输出和外部操作的实际权限。重要兼容约束或已批准的实验协议应写实；不把建议的实现细节当作验收。Codex 在边界内可调整实现、验证、优先级及局部路线。建议可以附理由；技术判断不扩大读写、Git、发布、数据或外部操作权限。
- **怎样验收和交付**：给出可观察的功能或研究判定标准和必要证据。需要时注明耗时预算、停止条件、恢复规则、Git／远端核验及特别回传要求。可选体验建议不能替代必要验收。

任务仍有实质取舍时，写清待决定的问题、已有证据和最值得先核验的事项。说明什么结果会让执行者继续、换路或停止，哪些判断已委托，以及适用的资源边界。

必要规则可用真实可读的项目路径引用。尚未落地、无法访问的附件如含必要内容，要把相关条款写进输入或另行提供实际可读来源。以当前用户授权、实际有效的项目合同及 Plan 为依据。条款有实质冲突时说明双方版本、差异及影响，暂停需要该决定的部分；其余已授权工作可继续。

## 3. 多个 Plan 汇入 Codex Hub

先按 Issue 链接或其他实际来源识别任务，适用时对照编号和修订，核对基线、依赖、重合目标、硬约束与共享资源。同一任务以当前有效输入执行；版本或任务归属确有冲突时澄清受影响项。共享工作可以只做一次，将证据关联到各自任务；不因为合并执行而合并验收口径。

多份 Plan 若依赖同一个足以改变路线或排程的待证前提，优先复用已有证据，或安排一次可共享的核验。由获委托的一方据此调整受影响的任务，独立工作照常推进。

有前置依赖、重叠写入、互斥资源或不可相容验证时合理串行。可隔离且收益明确时并行。资源、实验可比性与写入隔离按 [工程治理](06-ENGINEERING_GOVERNANCE.md)；跨目标、授权或评价协议的冲突交由有权方决定。在既有状态文档记录活跃任务的依赖、证据、下一步和重新取得 Plan 的线索，例如可共享的 Issue 链接或用户可重交的文件名。公共仓库省略私有绝对路径。新对话能恢复进度；执行前仍须读取有效输入，或确认实际项目合同已充分覆盖本次权限与验收。否则请用户重交，仅暂停依赖该输入的动作。

## 4. 回传与证据

普通任务用一份简洁的对话回执。正式交接带上 Issue 链接或其他实际来源，并按需注明编号／修订；交代完成情况、关键决定、必要验收与证据、真实交付和仍需处理的限制。研究／高风险任务注明实际基线、环境、实验或发布证据、偏差与停止依据。报告按需放入阶段记录或既有证据目录；无需逐任务结果文件。

明确区分实际通过、失败、未运行、不适用和当前不可获得，并用有效项目合同中的标签（如适用）。有效负面结论可以完成研究任务；数据泄漏、失效协议或缺失必要证据只支持相应的受限判断。必要真机、部署或远端验证缺失时，说明缺口，不能用模拟、其他环境或非阻塞建议替代。完成了实现不等于完成了全部验收与交付。
