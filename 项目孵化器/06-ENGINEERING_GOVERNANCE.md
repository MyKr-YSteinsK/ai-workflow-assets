# Engineering Governance｜项目权责与运行证据

孵化时从本基线选取适用条款，写进项目专属文档。根 `AGENTS.md` 写真实工作区、当前执行边界和必读入口；其他内容按任务加载。保留现有有效合同，未经授权不迁移旧项目。

## 1. 权责与自治

| 入口 | 工作方式 |
|---|---|
| GPT Project Main | 继续承担研究探索、规划、方案取舍及项目约定的路线／阶段评审；Codex 执行并写回真实状态。 |
| Codex Native | 直接从用户请求和仓库恢复，可自主调查、计划、开发、验证和收口，并推进项目已委托的路线或阶段。 |
| Codex Hub | 一条 Codex 对话协调多来源 Plan，整合依赖、去重、安排执行并汇总；按 [Plan 规范](05-CODEX_PLAN_SPEC.md) 在项目状态留下接手入口。无需额外服务或固定对话。 |

用户保留重大目标、重大研究方向、数据使用、验收口径及不可逆或超出授权的高风险操作。Codex 在已授权的边界内可调整技术路线、任务次序、局部假设、执行安排和验证方案，或停止缺乏价值的探索；用事实说明重要调整。实现、验证、证据接受、阶段推进、合并与发布分别判断。项目明确保留给 Main 或用户的决定不得由执行成功推导出来。

## 2. 本地环境与可恢复状态

建立新项目时，先记录适用的稳定信息。科研、Agent 或复杂工程应尽早核实环境、数据和关键运行链。按 [Bootstrap 合同](03-BOOTSTRAP_CONTRACT.md) 归入项目自己的 `docs/`；轻量项目可合并，已有项目优先用现有等价位置。

- **环境**：适用的 OS、CPU／内存／磁盘约束、GPU 型号与显存、关键驱动、语言运行时、虚拟环境和依赖锁。注明 canonical 环境、适用版本及最近核验依据，用实际路径或受控位置说明如何进入。
- **数据地图**：数据逻辑身份、版本、结构、基于项目或环境变量的目录映射、许可与使用边界、最后核验依据。敏感映射保存在获授权的私有位置；仓库只记录合适的安全引用。
- **运行**：已验证的安装、启动、测试和实验命令，工作目录、资源与输出位置。长任务按需记录日志、作业或后台状态查看、Checkpoint 与 Resume 的入口及适用条件。未运行的命令标作待验，使用现有工具和调度器。
- **故障经验**：记录可复用问题的触发条件、已验证根因、有效修复和适用范围；原因未验证时保留为待查。先复用档案，按需检查 GPU 占用、磁盘余量、活跃进程等动态事实；版本漂移只复核相关部分。
- **项目状态**：写明当前基线、实际能力和限制、在跑路线、证据、未解决事项与下一步。授权范围内在重要事实、环境、决定或阶段变化时更新；一次普通任务不要求机械改状态。实施事实与已批准决策分开。

## 3. 路线、资源与证据

先核实实际项目根目录、允许写入和运行的范围、工具输出与临时目录。父目录、同级项目和外部数据区不是默认可写位置；保护现有修改、已批准的 UX／研究基线和历史证据。

并行可涉及独立调研、子代理、实验进程或流水线。根据依赖、协调成本和实际收益决定并发：明确写入所有权、实验 ID、输出目录及数据、端口、数据库、GPU／显存资源，必要时用授权的工作树或运行目录隔离。工作树只隔离代码检出。共用 GPU 或同一输出无法隔离时串行；可独立前进的任务不用等待无关冲突。

实验比较记录适用的数据版本／切分、标签可见性、评价协议、基线、指标、环境及随机条件。协议不兼容时分开比较，避免后验真值或测试反馈进入调优。高成本运行按实际预算和停止依据迭代。路线结束或终止时总结问题、结论、限制和证据位置；重要阶段必要时汇总代价、可比结果、接受／停止理由和下一方向。保留无法重建或仍需审查的证据；报告的结论不能代替原始证据。

## 4. 文件生命周期

- 过程文件、可重建缓存和调试输出集中到已有有界位置。收口时整理本次生成、来源清楚且确认无价值的内容；保留他人使用、来源不明或仍具复现价值的文件。需要待清理区时使用一个已有或有实际收益的位置，不为检查模板新增目录。
- 将有效结论放入项目已有源文件和证据入口，大体积结果按项目授权存放并留定位信息。正式任务 Plan 由用户独立管理；仓库可保留 ID／修订与证据位置，无需 Plan 副本或例行结果文件。
- 提交前排除密钥、患者数据等敏感信息、受限路径／配置、无授权数据、依赖缓存和无价值生成物。Git 中删除文件不会清除历史。
- 有副作用的操作结果不明时先查询实际状态；同一失败重复且无新信息时改诊断路径。一般命令错误就地修正，把有长期价值的发现归入环境说明或故障经验。

## 5. Git 与外部交付

确认实际工作树、目标 remote／分支、权限及 Push 副作用；有适用变更时，只提交本任务内容，按已授权约定推送并观察实际远端。没有变更无需空提交。并行导致远端前进时，核对是否包含预期提交。必要远端步骤缺失时如实报告。

区分单纯 Push、会触发部署的 Push 和显式发布。Commit、Push、Merge、Deploy／Publish 各有独立权限和证据；授权不覆盖部署副作用时暂停受影响 Push，仅可使用已授权的其他目标。保护用户改动，不擅自初始化、创建远端、强制推送、改写历史或清理其他任务的文件。持久化报告保留已有证据版本，最终交付 SHA 在对话回执中报告，不回填进包含自身的提交。
