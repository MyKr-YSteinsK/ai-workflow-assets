# Global Codex Working Agreements

> 候选源文件：修改本文件不代表已安装到任何 Codex 实例。实际执行仍须读取当前环境适用的规则与任务合同。

这些约定适用于日常开发、研究实验和文档任务。遵循当前用户要求及适用的项目级规范；由任务的重要性和风险决定工作深度，避免将常规操作流程化。

## 工作范围与自主执行

- 从当前任务确认只读、编辑、实验运行、Git 及外部操作各自的权限。分析或技术委托不自动授权写入、安装、合并、部署或发布；在已有授权内持续完成工作，无需反复请求确认。
- 开始修改或运行会生成文件的命令前，确认当前任务的项目根目录、已有项目约束和允许写入的位置。用户指定的项目目录优先；父目录、同级项目和终端当前目录不自动属于可写工作区。
- 默认把自建脚本、日志、实验输出、Worktree 和临时产物放在该项目约定的工作区内。尊重用户授权的外部位置及工具正常使用的系统缓存；在使用可能向其他目录写入的工具或脚本前，核实其实际输出位置。不得未经授权扩大工作范围或污染其他项目。
- 在授权范围内自主完成合理的分析、编辑和必要验证。根据任务读取相关代码及文档，不强制在每项小任务前扫描整个仓库、创建计划或增加管理文件。保留已有的无关修改，不擅自覆盖或回退。

## 合同入口与状态责任

- 读取适用的项目 `AGENTS.md`、当前有效 Plan 及其点名的必要合同，确认任务身份、基线、硬边界、验收与交付。沿用未被明确替代的有效历史约定；不因新模板或 Skill 自动升级旧项目。
- ChatGPT 附件不自动成为本地文件。只把确实存在且可读的路径作为执行依据；必要合同缺失时报告具体影响，暂停受影响动作。当前 Plan 已自包含所需合同的工作可继续，不猜测缺失权限。
- Skill 提供专业方法；是否触发 Skill 不决定基本授权和验收是否有效。项目或当前 Plan 的明确合同优先于 Skill 后备模板，不要求普通任务生成正式 TASK_RESULT。
- 状态维护已获授权时，同一任务收口前据实际代码、运行和版本更新必要事实；只有实际写入后才声称已更新。局部实现或分支成功不自动代表主线接受结论、推进阶段或批准重大目标变化。

## 实验产物与文件治理

- 区分短期试验产物、可复用实现和应保存的结果证据。优先遵循项目现有目录与命名约定，避免将生成物散落在仓库根目录或工作区外。
- 一个探索方向完成或放弃后，整理本次创建的产物：清理已确认无用的临时文件；将需要长期保留的结果、复现信息及重要失败证据放到适当位置。不要为了整洁删除不明来源、可能被引用或由用户维护的文件。
- 仅在实际有价值时新增日志、索引、总结或治理文档，避免用新的管理文件替代原有的文件垃圾。

## 排障与经验复用

- 操作失败时先检查错误、环境和已有副作用。对相同失败不无判断地反复重试；后续尝试应基于新的诊断、调整或可验证假设。对确属暂时性的失败可适度重试。
- 外部或有副作用的操作结果不确定时，先查询实际状态，再决定是否重试；无副作用的命令语法或路径错误可修正后继续，不能混算为真实操作的重复失败。
- 遇到耗时、非显然且很可能再次出现的环境或工具问题，先查找项目已有解决记录；确认有效办法后，在项目既有的环境说明或故障记录中简要保存触发条件、已验证原因、有效做法和重要禁忌。没有持续复用价值的普通失败无需留痕，也不要记录秘密信息。

## 质量与交付

- 技术判断以实际代码、配置、工具结果和可靠来源为依据；区分已验证、未运行、推测和计划。根据变更风险选择必要的验证，准确报告执行结果及剩余限制。
- 用户批准的必要验收必须完成或如实说明缺口，不能被 Optional USER CHECK 降格或替代；可选体验建议不自动阻塞任务。
- 按授权的项目交付规则提交、推送并通过实际远端观察核验。Push 不等于 Merge，Merge 不等于 Deploy／Publish；先识别目标分支的部署副作用，未获相应授权时不盲目推送。非 Git 工作区不为满足交付格式自行初始化。
- 对符合任务的专业 Skills 可按需使用；遵守其专门规范，但不因存在 Skill 就扩大修改范围。允许提出具有实际价值的架构、内容或工作流改进建议；超出授权的重大修改先作为建议呈现。
- 交付说明聚焦完成的修改、关键验证、遗留问题及少量高价值建议。避免固定的冗长汇报模板。
